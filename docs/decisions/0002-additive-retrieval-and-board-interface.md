# ADR-0002：加法扩展检索维度与行动看板接口

## 状态

Accepted

## 日期

2026-08-09

## 背景

批次 4 治理核对发现三个缺口：真实 vault 的 13 个文件使用 YAML 列表形式 `tags:`，但 frontmatter 解析只支持单行 `key: value`，导致**按标签检索实际不可用**；`read_text(encoding="utf-8-sig")` 遇到非 UTF-8 文件直接抛异常，无容错；看板 `当前行动看板.md` 只能作为普通 Markdown 读取，没有结构化视图。

## 决策

在保持 ADR-0001 的四个既有工具名与返回结构不变的前提下，做加法扩展：

1. **检索维度补齐**：frontmatter 解析支持 YAML 列表（`tags:`/`aliases:`），检索打分新增"标签 25、链接目标 30"两个维度，形成标题/标签/链接/全文四维检索。既有字段与工具名不变。
2. **容错**：Markdown 以 `utf-8-sig` + `errors="replace"` 读入，非 UTF-8 文件不再崩溃；无法读取的文件在扫描中跳过。
3. **安全加固**：`read_section` 路径增加 260 字符上限（纵深防御，server 层已有 Field 校验）。
4. **新工具 `read_action_board`**：把 `当前行动看板.md` 解析为结构化列（H2+ 标题）、勾选项（`- [ ]`/`- [x]`）与子项，返回 open/done 计数与 frontmatter 日期。新增工具是加法，不破坏既有工具。

## 备选方案

- 给 `search_notes` 加独立 `by_tag` 参数：拒绝。把标签并入既有检索维度，保持参数面不变。
- 用 `read_section` 读看板全文：拒绝。结构化列/勾选/计数是看板接口的稳定契约，交给 Agent 自行解析会重复且易错。
- 解析非 UTF-8 时抛错提示：拒绝。个人 vault 混用编码时，替换符读入 + 文档说明比中断整个检索更符合只读接口的容错承诺。

## 后果

- 五个工具（四个既有 + `read_action_board`）；既有返回结构字段不变，`SearchHit` 未新增字段（标签经打分生效，不暴露新列）。
- 看板列解析规则（H2+、空列保留、子项剥离 `- ` 前缀）写入 `docs/contracts.md`，由确定性测试锁定。
- 未来若必须破坏既有契约（如改字段名、删工具），需新 ADR 并同步 `docs/contracts.md` 与 README。

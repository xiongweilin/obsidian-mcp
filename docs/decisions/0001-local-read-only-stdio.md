# ADR-0001：采用本地只读 STDIO MCP

## 状态

Accepted

## 日期

2026-08-08

## 背景

`D:\download\ratio` 只有数十个结构化 Markdown 文件，却包含会变化的 Windows、Docker 和云端事实。Agent 需要可重复定位事实源，并在必要时查询真实管理平面；固定向量索引会重复现有 frontmatter、Wikilink 和目录结构，也容易把历史快照误当当前事实。

## 决策

建立独立 Python 项目，通过 MCP Python SDK v2 暴露四个只读工具。文档检索在请求时扫描标题块并做确定性排序；运行时查询只调用预定义命令。Codex 通过本机 STDIO 启动服务，不开放网络端口、不建立数据库、不保存查询内容。

接口明确区分：

- `source_kind=documentation`：说明、导航或快照；
- `source_kind=runtime` 且 `is_live=true`：本次调用新取得的状态。

所有输出采用固定 Pydantic 模型；路径、数量和字符串长度在边界验证；常见凭据形式在返回前遮蔽。

## 备选方案

### 完整向量 RAG

拒绝。当前语料规模小且结构已足够，新增索引、embedding 和过期治理成本大于收益。若未来有真实评测证明确定性检索无法处理同义表达，可在 MCP 内部增加可选检索实现，而不改变工具契约。

### Streamable HTTP

暂不采用。当前仅供同一台 Windows 主机上的个人 Codex 使用；HTTP 会增加端口、认证和服务生命周期管理。需要跨机器或多人使用时再迁移。

### 任意命令工具

拒绝。它会把 MCP 变成远程 shell，扩大提示注入、秘密泄露和误操作风险。运行时查询必须继续采用代码内白名单。

## 后果

- Codex 可跨项目调用相同个人工具；源码和配置仍然分离。
- 每次检索扫描当前 Markdown，省去索引同步，但不适合数万文档规模。
- 云端状态依赖既有 SSH 包装器和网络连通性；失败会返回无敏感值的警告，不回退到旧文档冒充实时结果。
- 增加写操作、HTTP 暴露或持久化索引都需要新的 ADR 和明确授权。
